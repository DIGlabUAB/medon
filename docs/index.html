How it works

From a project description to an accountable plan.

No policy writing and no spreadsheet of clauses. The questions describe the tool. The rules decide what applies.

01  { Answer }

Describe the project

What it does, how much it acts alone, where it comes from, who sees it, what patient data it touches. Then what governance already exists.

function: clinical_supportsource: vendor_embeddedharm: serious
02  { Tier }

Get a risk tier with reasons

Low, moderate or high, with the answers that drove it. Unsure answers push the tier up and mark items to confirm.

lowmoderatehigh
03  { Plan }

Receive the checklist

Each item names the action, the evidence that proves it, the owner role and the framework clause it comes from. Print it or export it.

NIST AI RMF MANAGE 2.4JC and CHAI Element 4
The whole loop

Same questions. Your roles, your cadences.

Your institution file sets owner roles and review frequencies. Until it is filled, each item reads "Set by local policy", so the plan always reflects your decisions.

# Governance plan: Vendor sepsis early warning in the EHR

- Organization: Example Health System
- Clinical lead: Example Physician
- Date: 2026-10-04
- Risk tier: **high**
- Tier reasons: harm is serious

## Before deployment

- [~] **P01 Document intended use and limits** (in progress)
  - Do: Write the intended use, intended users, target population and out of scope uses. State the performance the tool is meant to deliver in this setting.
  - Evidence: Intended use statement or model card on file.
  - Owner: Clinical lead named on the project
  - Source: NIST AI RMF MEASURE 3.1 and 3.3 (N10); NIST AI RMF MEASURE 4.2 and 4.3 (N11); JC and CHAI RUAIH Element 6, risk and bias process (J10); EU AI Act Article 13, transparency and information to deployers (E04); ONC HTI-1 170.315(b)(11), source attributes (H01); WHO AI for health Principle 3, transparency, explainability and intelligibility (W03); CHAI Responsible AI Guide Stage 1, usefulness (R01); CHAI Responsible AI Guide Stage 1, transparency (R05); CHAI Responsible AI Guide Stage 2, transparency (R12); CHAI Applied Model Card Uses and directions (M02)
- [ ] **P02 Identify and document risks and biases** (open)
  - Do: List prospective risks and biases with emphasis on safety and access. Record the mitigations and the residual risk accepted.
  - Evidence: Risk register entry.
  - Owner: Director of Quality and Patient Safety
  - Source: JC and CHAI RUAIH Element 6, risk and bias process (J10); NIST AI RMF MEASURE 3.1 and 3.3 (N10); EU AI Act Article 9, risk management system (E01); ONC HTI-1 170.315(b)(11), risk analysis (H02); ISO/IEC 42001 Annex A.5, assessing impacts of AI systems (I03); CHAI Responsible AI Guide Stage 1, fairness (R03); CHAI Responsible AI Guide Stage 1, safety (R07); CHAI Responsible AI Guide Stage 2, safety (R10); CHAI Applied Model Card Warnings (M03)

Adopt it

Four steps to your own planner.

One file carries everything local. The rest is shared and versioned, so institutions can compare plans.

1

Install

Python 3.9 or later.

pip install medon
2

Fill the institution file

Role titles, review frequencies by tier, links to your own policies, extra local items.

cp org.example.yaml mysystem.yaml
3

Build your page

One self contained HTML file. Host it on any internal web server.

medon web --org mysystem.yaml -o planner.html
4

Extend

Add frameworks and regulations as controls and items. A test fails if a control is never used.

pytest

About

Built for governance leads who need a plan this week.

Health systems are asked to govern a growing set of AI tools. The guidance is published. Turning it into a project specific plan takes time that few teams have.

Medon reads a short description of a clinical AI project and writes the plan: a risk tier with reasons, a checklist of actions, the evidence that proves each one, the owner role and the source clause. Existing governance is recognised, so the list shows what is done, in progress and open.

Institutions set their own roles and review frequencies in one file. The planner runs offline in a single HTML page. Code is Apache 2.0. Data is CC BY 4.0. A study of 100 synthetic scenarios and the method are in the repository.
